# Interview Quiz — card-based interview trainer

A generic card-quiz engine for interview training. Ships with 15 seed question sets
(3 tracks × 5 levels, ~120 questions): **AI Engineer**, **Tech Lead**, and **Developer**,
from *basic* to *ultra-expert*. Any question set matching the JSON schema can be loaded —
generated by `scripts/generate_questions.py`, by the `/quiz-forge` Claude skill, or written
by hand.

## How it works

- **Cards**: multiple-choice questions are auto-graded; open "flashcard" questions flip to a
  model answer you self-rate (nailed / partial / missed). Every question carries a
  **difficulty tag** (basic → ultra-expert) and an **interview-typicality tag**
  (staple / common / occasional / curveball — how often interviewers actually ask it).
- **Level gate**: level N+1 of a track unlocks when the latest answers on level N average
  **≥ 80%** across at least half of its questions.
- **Modes**: study a level, run the *Typical interview drill* (staples + commons only), or
  the *Weak-spot mix* (your lowest-scoring cards first — sessions always serve weakest cards
  first).
- **Results**: every answer is stored; `/api/results/export` returns a performance summary
  (per-track levels, weak/strong topics) that the `/quiz-forge` skill uses to generate the
  next, harder question set.

## Architecture

| Piece | Tech |
|---|---|
| Backend | Python 3.11, FastAPI, SQLAlchemy 2.0, Pydantic v2 |
| Frontend | TypeScript (strict), Vite, no framework — plain DOM modules |
| Database | Postgres (Neon) in production, SQLite locally — same code path |
| Deploy | Vercel: static frontend + Python serverless function (`api/index.py`) |

```
app/schemas.py        ← the question-set JSON contract (single source of truth)
app/models.py         ← DB tables: question_sets, questions, quiz_sessions, answers
app/services/         ← grading rules, stats, set import/selection (pure logic, unit-tested)
app/routers/          ← thin HTTP layer: /api/sets, /api/quiz, /api/results
frontend/src/         ← typed API client + card UI (types mirror the Pydantic schemas)
data/question_sets/   ← versioned question sets (JSON)
scripts/seed.py       ← validate + load sets into the DB
scripts/generate_questions.py ← generate a set for ANY topic via the Claude API
```

## Local development

```bash
cd quiz-app
pip install -r requirements.txt -r requirements-dev.txt
python scripts/seed.py                 # validate + load the seed sets into ./quiz.db
cd frontend && npm install && npm run build && cd ..
uvicorn app.main:app --reload          # serves the app at http://127.0.0.1:8000
```

For frontend live-reload, run `npm run dev` in `frontend/` alongside uvicorn — Vite proxies
`/api` to port 8000.

Quality gates:

```bash
python -m pytest          # 45 tests: schema contract, grading, full API flow
ruff check .              # lint
mypy                      # strict type-check of app/
cd frontend && npm run typecheck
```

## Deploy to Vercel (private)

1. **Database**: create a free Postgres database at [neon.tech](https://neon.tech)
   (or via Vercel Marketplace → Neon). Copy the connection string.
2. **Vercel project**: import this GitHub repo at [vercel.com/new](https://vercel.com/new) and
   set **Root Directory** to `quiz-app`. `vercel.json` handles the build (frontend → static,
   `api/index.py` → Python function).
3. **Environment variable**: add `DATABASE_URL` = the Neon connection string
   (Settings → Environment Variables).
4. **Seed the production DB** from your machine:
   ```bash
   cd quiz-app
   DATABASE_URL="postgres://…neon.tech/…" python scripts/seed.py
   ```
5. **Keep it private**: Project → Settings → Deployment Protection → enable
   **Vercel Authentication** for Production (free on all plans — only you, logged into Vercel,
   can open the app). The app itself has no auth; privacy comes from this layer.

Redeploys pick up new question sets committed to `data/question_sets/` after you re-run the
seed step — or skip redeploying entirely and paste a set's JSON into the app's **Import set**
page.

## Generating new questions

**Any topic, via the admin script** (needs `ANTHROPIC_API_KEY`):

```bash
python scripts/generate_questions.py --topic "Kubernetes" --track ai-engineer --level 4 --count 10
python scripts/generate_questions.py --topic "SQL tuning" --track developer --level 3 --seed
```

The output is validated against the shared schema, refuses duplicate prompts, and lands in
`data/question_sets/`.

**Results-driven, via Claude Code**: run `/quiz-forge` in the repo. It reads your results
export, finds your weak topics and current level, and writes a set one notch harder —
targeted at exactly what you keep getting wrong.

## Question-set JSON schema (the contract)

```jsonc
{
  "id": "kubernetes-l4",           // lowercase-hyphen slug, unique
  "title": "Kubernetes — Expert",
  "track": "ai-engineer",          // any slug; new tracks appear automatically
  "level": 4,                      // 1..5
  "questions": [
    {
      "id": "pod-eviction",        // unique within the set
      "type": "mc",                // "mc" | "flashcard"
      "topic": "Kubernetes",
      "prompt": "…the question as an interviewer would ask it…",
      "options": ["…", "…", "…"],  // mc only, 2-6 entries
      "correct_index": 0,           // mc only
      "answer_notes": "…teaches the answer + bonus-credit points…",
      "difficulty_rationale": "…why this is level 4…",
      "tags": {
        "difficulty": "expert",    // basic|intermediate|advanced|expert|ultra-expert
        "typicality": "common",    // staple|common|occasional|curveball
        "topics": ["kubernetes", "scheduling"]
      }
    }
  ]
}
```

Validation lives in `app/schemas.py` (`QuestionSetFile`); check any file with
`python scripts/seed.py --validate <file>`.
